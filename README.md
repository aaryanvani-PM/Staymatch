# StayMatch: Conversational Stay Search

A prototype travel search where you describe the stay you want in plain language instead of clicking through filter dropdowns. It turns the request into hard filters and softer preferences, backs every match with cited review evidence, and helps you compare finalists side by side.

**Status:** Working prototype. Built in Google AI Studio; exported to GitHub on 22 October 2026.

## What it does

- **Understands the request.** A query like "quiet beach villa for a family, walkable to cafés, under $300" is split into hard filters (budget, property type) and soft signals (quiet, walkable) that are checked against reviews.
- **Shows evidence, not just a score.** Each match cites the review snippets behind it, so the user can see why a property was recommended.
- **Compares three options.** A trade-off drawer lines up up to three pinned stays and writes a short verdict on which fits which priority.
- **Tracks product metrics.** A metrics drawer outlines how the search would be measured and A/B tested against the existing filter experience.

## How it works

React and Vite front end, Express server (`server.ts`) calling the Gemini API through `@google/genai`.

| Endpoint | What it does |
|---|---|
| `POST /api/decompose` | Turns the natural-language query into structured filters and review signals |
| `POST /api/tradeoff` | Writes the three-way comparison verdict |

The evidence matching runs in `src/lib/evidenceEngine.ts`.

## What's real and what's simulated

**Real, when a Gemini API key is set**
- Query decomposition and the trade-off verdict are generated by a Gemini Flash model.

**Simulated or assumed**
- The catalog is a small sample of six properties with sample reviews (`src/data/properties.json`), not live inventory.
- Without a key, or if a call fails, both endpoints fall back to a rule-based engine so the demo keeps working.
- The metrics and A/B framework describe how the feature would be measured. No experiment has been run with real users.

## What I learned

- The hard part of conversational search is separating must-haves from nice-to-haves. Treating "quiet" as a filter instead of a preference empties the results.
- Users trust a recommendation more when they can see the review evidence behind it, so citations are a product feature, not decoration.
- The right baseline for a test is the existing filter flow, with search-to-booking conversion as the primary metric and misunderstood queries as a guardrail.

## Next steps

- Measure how often the decomposer misreads a request.

## Run it locally

Requires Node.js.

```bash
npm install
cp .env.example .env    # add your own GEMINI_API_KEY; never commit .env
npm run dev
```

Without a key, the app uses its rule-based fallback.
